Introduction back to ToC

Data ecosystems bring together autonomous participants that exchange data and services across organisational boundaries. Building and operating them requires knowing three things at once: which technical components exist and how they depend on each other, which processes the ecosystem runs, and which process step calls which API endpoint with which data. Architecture vocabularies cover the first, process vocabularies the second, and API descriptions such as OpenAPI cover single interfaces. None of them states the connection between a process and the components that realise it.

DEDL-O, the Data Ecosystem Description Language Ontology, describes all three as layers of one graph:

  • Architecture layer: the technical elements of an ecosystem (dedl:TechnicalDataEcosystemElement with subclasses such as dedl:API, dedl:IdentityProvider or dedl:Storage), their directed dependencies (dedl:dependsOn) and who operates them (dedl:operatedBy).
  • Process layer: processes, service tasks, gateways and sequence flows, reused from the BPMN-based ontology BBO (dedl:Process is a subclass of BBO:Process), with declared input and output sets.
  • Integration layer: which service task invokes which endpoint (dedl:invokesEndpoint) and how each request parameter is filled (dedl:ParameterMapping, with exactly one of a source value, a constant or a template).

The integration layer is constrained by the architecture layer: whoever executes a process must depend on every component the process invokes. Validation rules that connect the layers in this way are part of the resource.
